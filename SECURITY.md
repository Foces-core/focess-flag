# Security Policy

## Supported versions

Until versioned releases are published, security fixes are intended for the
latest state of the `main` branch. There is currently no separate list of
supported release branches.

## Reporting a vulnerability

**Please do not report security vulnerabilities in public GitHub issues,
discussions, or pull requests.**

Use GitHub's private vulnerability reporting or security advisory feature for
this repository, if it is enabled. If it is unavailable, contact one of the
repository's listed code owners privately through GitHub and ask for a secure
reporting channel. Do not include sensitive exploit details in a public
message.

When reporting, include as much of the following as you can safely provide:

- A description of the potential vulnerability and its impact.
- The affected files, component, or commit, if known.
- Clear reproduction steps or a minimal proof of concept.
- Any mitigations or remediation ideas you have considered.

Please allow maintainers reasonable time to investigate and coordinate a fix
before publicly disclosing the issue. We will make a reasonable effort to
acknowledge private reports and share updates, but no response or remediation
timeline is guaranteed.

## Scope

Report vulnerabilities in this repository's code, configuration, or automation.
For vulnerabilities in a third-party dependency or service, use that provider's
own security reporting process as well; you may also privately notify this
project if the issue affects FOCES Flag.
